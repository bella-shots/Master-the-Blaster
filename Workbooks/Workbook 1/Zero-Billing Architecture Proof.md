# Zero-Billing Architecture Proof

> Source: `Phase_1_Product_Architecture_Google_AI_Studio_AUTONOMOUS_REVISED.xlsx`

| PHASE 1 — ZERO-BILLING ARCHITECTURE PROOF |  |  |  |  |  |  |
| --- | --- | --- | --- | --- | --- | --- |
| Purpose | Prove the selected architecture satisfies the hard invariant: ₹0 additional software/service spend beyond the existing Google AI Pro subscription, with no mandatory Cloud Billing/Blaze dependency. |  |  |  |  |  |
| Rule | Do not delete Express/server.ts before this proof. Do not migrate production architecture merely because Firebase Hosting works. Prove the whole application boundary first. |  |  |  |  |  |
| ID | Proof item | What AI must verify | Pass condition | Failure / STOP condition | Evidence to leave in repo | Status |
| ZBA-01 | Firebase Hosting static SPA | Can the React/Vite SPA be deployed on Firebase Hosting without linking a Cloud Billing account? Record current Spark/no-billing eligibility and quotas. | Successful deployment and route smoke test without billing linkage. | Billing account required, quota incompatible with expected app, or deployment path silently upgrades to Blaze. | Deployment output + hosting configuration + documented current quota/source evidence. | Not Started |
| ZBA-02 | Firebase Auth | Can required users authenticate and be mapped to roles without a billing-dependent auth service? Verify selected providers and application role mapping. | Authenticated user identity is available to the client and maps deterministically to an application role. | Required auth provider requires billing or cannot support the user model without an unapproved paid dependency. | Auth test + role mapping + configuration notes. | Not Started |
| ZBA-03 | Firestore + Security Rules | Can Projects/Finance/HR/builder metadata be accessed directly from the web client while enforcing role/module/page/project restrictions with Security Rules? | Unauthorized reads/writes are denied; authorized operations succeed; no privileged mutation relies solely on hidden UI. | Rules cannot enforce required boundary, or a server path becomes mandatory and has no no-billing solution. | Rules files + emulator/controlled tests + permission matrix. | Not Started |
| ZBA-04 | Google Drive | Can required Excel/document/image upload and metadata workflows use Drive OAuth/API without exposing client secrets or requiring a billing-dependent backend? | Required Drive operations work or the exact supported integration boundary is proven and documented. | Operation requires secret server credentials, billing-dependent service, or an unresolved OAuth/permissions dependency. | OAuth scopes + controlled upload/list/read test or documented limitation. | Not Started |
| ZBA-05 | Gmail | Can MOM-finalized email behavior meet the product requirement without a mandatory billing-dependent backend? Separate interactive user-authorized sending from unattended sending. | Required email behavior is demonstrably supported under the chosen architecture, or the exact limitation is documented and escalated before architecture freeze. | Unattended sending requires a backend/service that violates the invariant, or required OAuth scopes/consent remain unresolved. | Controlled send test, OAuth design, trigger model, and limitation/decision record. | Not Started |
| ZBA-06 | Gemini / AI functionality | Can any required Gemini functionality operate without exposing unrestricted API keys in the client and without mandatory billing? Identify whether AI is core, optional, or dev-time only. | Required AI capability works within a verified no-billing path, or is explicitly redesigned as optional/non-runtime-critical. | Required production AI path requires billing, exposes secrets, or depends on an unavailable no-billing capability. | AI dependency map + secret-handling decision + controlled test if applicable. | Not Started |
| ZBA-07 | End-to-end invariant | Do all required production dependencies remain on the no-billing path together? | Every mandatory production dependency is PASS; no Cloud Billing/Blaze is required; no paid SaaS/plugin is mandatory. | Any mandatory dependency requires billing or an unresolved paid service. | Final dependency matrix + explicit architecture decision. | Not Started |
| Decision rule | Only after ZBA-01 through ZBA-07 are PASS may Phase 1 freeze the production hosting/backend architecture. If any item is OPEN/FAIL, stop at the corresponding Human Gate and do not claim Phase 1 complete. |  |  |  |  |  |
| Current external evidence (verify again during execution) | Firebase documentation currently states Firebase Hosting offers a no-cost tier with no billing account required for small deployments; Firebase App Hosting requires Blaze; Cloud Run requires a Cloud Billing account; Firebase Firestore web clients can use Auth + Security Rules for serverless authorization. |  |  |  |  |  |
